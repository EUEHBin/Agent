## 2. 第 12 讲 · 测试方案 ——「测什么、测到哪一层」

### 四种测试（面试常问，用快递类比）

| 名字 | 测什么 | 前端类比 |
|------|--------|----------|
| **单元测试 unit** | 一个函数/类，尽量不碰真数据库、真网络 | 测一个纯函数 `formatPrice` |
| **集成测试 integration** | 好几块拼在一起（路由+service+DB） | 测一个 API hook + mock server，或连测试库 |
| **e2e** | 几乎当真系统跑一条业务链 | Playwright 走完登录→下单 |
| **冒烟 smoke** | 生命线：挂了用户立刻没法用 | 「首页能开、能登录」这种红线用例 |

冒烟往往打在**已经稳定的核心能力**上（登录、下单、支付回调），不是每个新小功能都标 smoke。

### Stub vs Mock（一句话）

- **Stub**：换成假实现，固定返回「成功发短信」。  
- **Mock**：不但假，还能查「你有没有调用、传了什么参数」。  
课说：多数情况 Mock 能代替 Stub。

### 开发日常顺序

写功能 → 相关测试绿 → 冒烟绿 →（可选）覆盖率 → 再提 PR。

## 3. 第 13 讲 · 三层架构 ——「为什么要拆 api / service / model」

### 用前端话讲

- 页面组件里不写复杂业务 → 抽到 `services/`  
- 后端也一样：  
  - **api**：只负责收 HTTP（像页面事件处理）  
  - **service**：业务规则（像 service 层）  
  - **model**：表结构（像和 DB 对应的类型/实体）  
  - **schema**：接口入参出参形状（像 TS interface / zod）

### 额外概念

- **DTO / BO**：给接口看的形状 ≠ 给业务内部用的形状 ≠ 数据库表。  
- **依赖倒置**：上层依赖「抽象」（接口），方便换成假实现来测——和前端可注入依赖一个道理。

这节可以少敲代码，但**分层名字要能说清**。

## 4. 第 14 讲 · 文件上传 ——「文件别经过你的 Node/Python 中转」

### 错误直觉

用户选图片 → 上传到你的 FastAPI → FastAPI 再传到 OSS。  
问题：服务器带宽、内存、超时都吃紧。

### 课推荐的模式（直传）

```text
1. 前端向你的后端要「临时上传凭证」
2. 后端根据系统设置里的 OSS 密钥，签发短时凭证（不传文件本体）
3. 前端拿凭证，把文件直接 PUT 到阿里云 OSS
4. 成功后前端把 URL 告诉业务后端（如写到商品图字段）
```

类比：不是把快递先寄到你家再转发，而是驿站给你一张「可直接投柜」的条码。

### 工程里看什么

`UploadService.generate_upload_sign`：校验后缀/MIME → 读 OSS 配置 → 调 `AliyunOSSUploader.generate_upload_credentials`。  
没阿里云账号可以不真跑，但模式一定要懂。

## 6. 第 16 讲 · 长事务 / 短事务 ——「慢事情别霸占数据库连接」

### 问题

数据库连接池里连接数量有限（比如几十个）。  
如果你：

```text
打开 DB 会话 → 开始调大模型（等 30 秒）→ 全程占着连接 → 写回结果
```

那高峰时连接会被「干等 AI」占满，别人登录都变慢。

### 正确拆法（短事务）

```text
① 短时间：查库、校验用户、读商品、读配置
② commit + close：把连接还回池子
③ 慢 IO：调 OSS / 调大模型（可以流式很久）
④ 再拿会话：把结果 merge/flush 写回
```

AI 导购代码里就是这样写的（见第 19 讲 `ai_service.py`）：流式开始前 `await self.db.commit(); await self.db.close()`。

前端类比：别在 `await fetch(大文件)` 期间还占着唯一的 DB 连接；先查完再慢慢下。

## 7. 第 17 讲 · 用户系统 ——「登录到底在保什么」

### 7.1 密码怎么存

- **绝不**存明文 `123456`。  
- 裸 SHA256 也不够：黑客有彩虹表。  
- 课用 **bcrypt**：自动加盐 + 慢哈希，同样密码每次存库字符串都不同，但 `verify` 能校验。

### 7.2 JWT 是什么（前端最熟）

登录成功后服务器给你一串 token（可放 `localStorage` / cookie）。  
里面有用户 id、过期时间等，用**服务器密钥**签过名——改内容验签会失败。

- 密钥、过期时间 → 配置/设置里  
- 「需不需要给 JWT 再加一层盐？」课里留了思考：JWT 已有密钥签名，重点是**密钥保密、过期、传输用 HTTPS**，不是再套一层业务盐。

### 7.3 接口怎么「必须登录」

```text
路由参数里 Depends(get_current_user)
  → 从 Authorization: Bearer xxx 取 token
  → decode → 查 User 表
  → 得到当前用户对象
```

类比：路由守卫 + `useAuth()`。  
OpenAPI 文档上会显示小锁，表示要带认证。

### 7.4 ContextVar

异步里多个请求并发，不能用全局变量存「当前用户」，会串号。  
`ContextVar` = 每个异步任务自己的「ThreadLocal」。  
日志里的 `request_id` 也常靠它在整条调用链传递。

对照文件：`20.../app/core/auth.py`。

## 8. 第 18 讲 · 日志 ——「出了事怎么查」

### 用什么库

**loguru**：比标准 logging 好写。启动时 `setup_logging()` 配好。

### 生产 vs 开发

- 生产：打 **JSON** 到 stdout，方便云日志采集。  
- 开发：人能读的文本；错误可额外落文件。

### 记三类东西

| 类型 | 谁写 | 典型字段 |
|------|------|----------|
| 请求日志 | 中间件 | method、path、status、耗时、client_ip |
| 数据库日志 | SQLAlchemy 事件 | sql、耗时；慢查询 warning |
| 业务日志 | service 里主动打或装饰器 | action、entity_id |

### request_id 为什么重要

一次请求进门就生成 UUID，整条链路日志都带上。  
前端报「某次聊天失败」，你用这个 id 就能在日志里串起：请求 → SQL → AI 调用。

对照：`20.../app/core/middleware/logging.py`（进门设 `request_id_var`，挂 `RequestLog`）。

## 10. 第 20 讲 · 流式响应 ——「边生成边给前端」

### 为什么要流式

模型生成要好几秒到几十秒。若等全部生成完再 `return JSON`，用户以为卡死。  
流式 = 每出几个字就推一次，聊天框逐字出现。

### SSE（本课 AI 问答主推）

```text
浏览器 ──HTTP──► 服务器
服务器 ──不断 data: xxx\n\n──► 浏览器（连接一直开着）
```

- 单向：主要是服务器推  
- 还是 HTTP，好过网关、好调试  
- 课件格式：`data: 内容\n\n`；错误可用 `event: error\ndata: ...\n\n`

### WebSocket

```text
先 HTTP 握手升级成 WS
然后两边都能随时发消息
```

适合要双向、高频、Agent 多轮推状态的场景。

### 和中间件/异常的坑（一定要懂）

| | SSE | WebSocket |
|--|-----|-----------|
| HTTP 中间件 | 建连时过；**后续 chunk 不再过** | 基本不过 HTTP 中间件 |
| 全局异常 handler | 流开始后异常**不会**自动变 JSON 错误体 | 也不会走那套 |
| 所以 | 生成器里自己 `yield event: error` | 自己 `send_json({type:error})` |

统一成功包装中间件看到 `request.state.is_stream = True` 会**跳过**，否则会把流式响应当成普通 body 乱包一层。

对照：

- `app/api/ai_sse.py`  
- `app/api/ai_ws.py`  
- `app/core/middleware/response.py` 里的 `is_stream` 判断  

### 前端 demo（你一定要看）

`demo/ai-demo/` 就是给这套后端配的 React 演示：

- `src/services/sse.ts`：fetch + `ReadableStream` 读 `data:` 行  
- `src/hooks/useSSEChat.ts`：拼消息、streaming 状态、abort  
- `src/hooks/useWebSocketChat.ts` + `services/websocket.ts`：WS 版  
- `src/context/AuthContext.tsx`：token  

用你熟悉的 React 视角看一遍，再回看 Python，会通很多。
